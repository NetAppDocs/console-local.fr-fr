. Assurez-vous de disposer des autorisations nécessaires dans Azure pour créer une application Active Directory et pour l'attribuer à un rôle.
+
Pour plus de détails, veuillez consulter https://docs.microsoft.com/en-us/azure/active-directory/develop/howto-create-service-principal-portal#required-permissions/["Documentation Microsoft Azure : autorisations requises"^]

. Depuis le portail Azure, ouvrez le service *Microsoft Entra ID*.
+
image:screenshot_azure_ad.png["Affiche le service Active Directory dans Microsoft Azure."]

. Dans le menu, sélectionnez *App registrations*.
. Sélectionnez *Nouvelle inscription*.
. Veuillez préciser les détails concernant l'application :
+
** *Nom* : Saisissez un nom pour l’application.
** *Type de compte* : Sélectionnez un type de compte (tous fonctionneront avec la NetApp Console).
** *URI de redirection* : Vous pouvez laisser ce champ vide.


. Sélectionnez *Register*.
+
Vous avez créé l'application Active Directory et le service principal.



. Créer un rôle personnalisé :
+
Notez que vous pouvez créer un rôle personnalisé Azure à l'aide du portail Azure, d'Azure PowerShell, de l'interface CLI Azure ou de l'API REST. Les étapes suivantes indiquent comment créer le rôle à l'aide de l'interface CLI Azure. Si vous préférez utiliser une autre méthode, reportez-vous à https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles#steps-to-create-a-custom-role["Documentation Azure"^]

+
.. Copiez le contenu du link:reference-permissions-azure.html["autorisations de rôle personnalisées pour l’agent de la Console"] et enregistrez-le dans un fichier JSON.
.. Modifiez le fichier JSON en ajoutant les ID d'abonnement Azure à l'étendue assignable.
+
Vous devez ajouter l'ID de chaque abonnement Azure à partir duquel les utilisateurs créeront des systèmes Cloud Volumes ONTAP.

+
*Exemple*

+
[source, json]
----
"AssignableScopes": [
"/subscriptions/d333af45-0d07-4154-943d-c25fbzzzzzzz",
"/subscriptions/54b91999-b3e6-4599-908e-416e0zzzzzzz",
"/subscriptions/398e471c-3b42-4ae7-9b59-ce5bbzzzzzzz"
----
.. Utilisez le fichier JSON pour créer un rôle personnalisé dans Azure.
+
Les étapes suivantes décrivent comment créer le rôle à l'aide de Bash dans Azure Cloud Shell.

+
*** Démarrez https://docs.microsoft.com/en-us/azure/cloud-shell/overview["Azure Cloud Shell"^] et choisissez l’environnement Bash.
*** Téléversez le fichier JSON.
+
image:screenshot_azure_shell_upload.png["Capture d'écran d'Azure Cloud Shell où vous pouvez choisir l'option permettant de charger un fichier."]

*** Utilisez l’Azure CLI pour créer le rôle personnalisé :
+
[source, azurecli]
----
az role definition create --role-definition Connector_Policy.json
----
+
Vous devriez maintenant disposer d'un rôle personnalisé appelé Console Operator que vous pouvez attribuer à la machine virtuelle de l'agent de console.





. Attribuez l'application au rôle :
+
.. Dans le portail Azure, ouvrez le service *Subscriptions*.
.. Sélectionnez l’abonnement.
.. Sélectionnez *Contrôle d’accès (IAM) > Ajouter > Ajouter une attribution de rôle*.
.. Dans l'onglet *Rôle*, sélectionnez le rôle *Console Operator* et sélectionnez *Suivant*.
.. Dans l'onglet *Membres*, complétez les étapes suivantes :
+
*** Conservez l’option *Utilisateur, groupe ou principal de service* sélectionnée.
*** Sélectionnez *Sélectionner les membres*.
+
image:screenshot-azure-service-principal-role.png["Capture d'écran du portail Azure affichant la page Membres lors de l'ajout d'un rôle à une application."]

*** Recherchez le nom de l'application.
+
Voici un exemple :

+
image:screenshot_azure_service_principal_role.png["Capture d'écran du portail Azure montrant le formulaire « Ajouter une attribution de rôle » dans le portail Azure."]

*** Sélectionnez l'application et sélectionnez *Sélectionner*.
*** Sélectionnez *Suivant*.


.. Sélectionnez *Révision + attribution*.
+
Le principal de service dispose désormais des autorisations Azure requises pour déployer l’agent de la Console.

+
Pour déployer Cloud Volumes ONTAP à partir de plusieurs abonnements Azure, vous devez lier le principal de service à chacun de ces abonnements. Dans la NetApp Console, vous pouvez sélectionner l’abonnement que vous souhaitez utiliser lors du déploiement de Cloud Volumes ONTAP.





. Dans le service *Microsoft Entra ID*, sélectionnez *App registrations* et sélectionnez l'application.
. Sélectionnez *API permissions > Add a permission*.
. Sous *Microsoft APIs*, sélectionnez *Azure Service Management*.
+
image:screenshot_azure_service_mgmt_apis.gif["Une capture d'écran du portail Azure qui montre les autorisations de l'API Azure Service Management."]

. Sélectionnez *Accéder à Azure Service Management en tant qu’utilisateurs de l’organisation*, puis sélectionnez *Ajouter des autorisations*.
+
image:screenshot_azure_service_mgmt_apis_add.gif["Capture d'écran du portail Azure montrant l'ajout des API Azure Service Management."]



. Dans le service *Microsoft Entra ID*, sélectionnez *App registrations* et sélectionnez l'application.
. Copiez l’*ID de l’application (client)* et l’*ID du répertoire (tenant)*.
+
image:screenshot_azure_app_ids.gif["Une capture d'écran qui montre l'ID de l'application (client) et l'ID du répertoire (locataire) pour une application dans Microsoft Entra IDy."]

+
Lorsque vous ajoutez le compte Azure à la Console, vous devez fournir l'ID d'application (client) et l'ID d'annuaire (locataire) de l'application. La Console utilise ces ID pour se connecter par programmation.



. Ouvrez le service *Microsoft Entra ID*.
. Sélectionnez *App registrations* et sélectionnez votre application.
. Sélectionnez *Certificats et secrets > Nouveau secret client*.
. Fournissez une description du secret et une durée.
. Sélectionnez *Add*.
. Copiez la valeur du secret client.
+
image:screenshot_azure_client_secret.gif["Capture d'écran du portail Azure affichant un secret client pour le service principal Microsoft Entra."]
